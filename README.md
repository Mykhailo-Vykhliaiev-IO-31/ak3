# Лабораторна робота №3

## Дисципліна

Архітектура комп’ютерів

## Тема

Завантажувач основної програми. Обробка виключень. Вивід даних на відлагоджувальний порт або консоль

## Виконав

Вихляєв Михайло, група ІО-31

## Мета роботи

Навчитися працювати з оперативною пам’яттю, використовувати інструкції спеціального призначення, працювати з виключеннями процесора Cortex-M4, створити мінімальний завантажувач системи та реалізувати вивід даних у консоль за допомогою semihosting.

## Варіант

Варіант лабораторної роботи визначається за номером залікової книжки:

```text
3104 % 16 = 0

Отже, виконується варіант №0.

У варіанті 0 потрібно використати:

Команди для роботи з пам’яттю: LDR, STR
Інкремент/декремент регістру адреси: інкремент
Вид зсуву: числовий
Кількість байт для зсуву: 4

У файлі bootloader.S для цього використано інструкції:

str r1, [r6], #4
ldr r2, [r7], #4
Використані інструменти
Ubuntu / WSL
arm-none-eabi-gcc
binutils-arm-none-eabi
make
xPack QEMU ARM
Semihosting
BKPT #0xAB
Опис файлів проєкту
start.S - стартовий асемблерний файл, який містить векторну таблицю, обробник скидання __hard_reset__, ініціалізацію stack pointer та виклик bootloader.
bootloader.S - файл із реалізацією bootloader. У ньому демонструється робота з пам’яттю за варіантом 0 за допомогою інструкцій LDR та STR.
kernel.S - основна програма, яка виконує обчислення з лабораторної роботи №2 та виводить результат у консоль.
print.S - файл із процедурами dbgput та dbgput_line для виводу рядків у консоль через semihosting.
lscript.ld - скрипт лінкера, у якому описано області пам’яті FLASH та RAM.
Makefile - файл для автоматизації компіляції, лінкування та запуску проєкту в QEMU.
firmware.elf - виконуваний ELF-файл прошивки.
firmware.bin - бінарний файл прошивки.
Логіка роботи програми

Після запуску програми виконання починається з файлу start.S.

У файлі start.S:

Створюється векторна таблиця.
Ініціалізується stack pointer.
Викликається функція bootload з файлу bootloader.S.

У файлі bootloader.S:

Виводиться повідомлення:
bootloader started
Демонструється робота з пам’яттю відповідно до варіанту 0:
str r1, [r6], #4
ldr r2, [r7], #4
Викликається основна програма kernel_main.

У файлі kernel.S:

Виводиться повідомлення:
kernel started
Виконується обчислення з лабораторної роботи №2.
Виводиться результат:
result: 35
Обчислення в kernel.S

У програмі використано значення:

a = 4
b = 3
c = 5

Формула з лабораторної роботи №2:

якщо a*b >= 10:
    result = (a | b) * c

якщо a*b < 10:
    result = (a*b) * c

Обчислення:

a*b = 4*3 = 12
12 >= 10

a | b = 4 | 3 = 7
result = 7*5 = 35

Отже, очікуваний результат:

result: 35
Semihosting

Для виводу повідомлень у консоль використовується механізм semihosting.

У файлі print.S використано інструкцію:

bkpt #0xAB

Для виводу рядка використовується операція:

#define SYS_WRITE0 #0x04

Процедура dbgput виводить рядок, адреса якого передається через регістр r0.

Процедура dbgput_line виводить рядок та символ нового рядка.

Збірка проєкту

Для очищення попередніх результатів збірки:

make clean

Для збірки проєкту:

make

Після виконання команди make створюються файли:

start.o
bootloader.o
kernel.o
print.o
firmware.elf
firmware.bin
Запуск QEMU

Для запуску програми в QEMU використовується команда:

make qemu

QEMU запускає прошивку для плати STM32F4-Discovery з мікроконтролером STM32F407VG та увімкненим semihosting.

Очікуваний результат

Після запуску програми в QEMU у консолі має з’явитися:

bootloader started
kernel started
result: 35

Це означає, що:

Стартовий код успішно передав керування bootloader.
Bootloader виконав демонстрацію роботи з пам’яттю.
Kernel-програма була успішно запущена.
Результат обчислення було виведено у консоль через semihosting.
Висновок

У результаті виконання лабораторної роботи було створено програму для ARM Cortex-M4, яка містить стартовий код, bootloader, основну програму kernel та процедури для виводу повідомлень у консоль. Було використано інструкції роботи з пам’яттю LDR та STR відповідно до варіанту 0, а також реалізовано вивід даних через semihosting за допомогою інструкції BKPT #0xAB.

Проєкт було успішно зібрано за допомогою Makefile та запущено в емуляторі QEMU. У результаті виконання програми в консолі було отримано повідомлення bootloader started, kernel started та result: 35, що підтверджує правильність роботи програми.
